# Zenthos Gym

Membership, door check-in and renewals for gyms with one or many branches. Members pay and check in from their phone, the front desk confirms transfers and watches the door live, and the owner sees revenue and attendance across every branch.

## What it does

- **Members**: membership status and days left, renew by card (Paystack) or bank transfer with a receipt, scan the entrance code to check in, invite friends for free days, push notifications.
- **Front desk** (one branch): live check-in feed with distinct sounds, members list with photos, register members from a paper form (email optional), record cash, confirm transfers, reset a member's password, print the branch entrance code.
- **Admin** (every branch): revenue and attendance overview, plans and pricing, branches, staff, gym settings.

The app is a PWA. Members install it from the browser; iPhones need it added to the Home Screen before web push works.

## Stack

| Layer | Choice |
| --- | --- |
| App | Next.js 14 (App Router), React 18, TypeScript (strict), Tailwind CSS |
| Data | Supabase: Postgres with row level security, Auth, Storage, Realtime, pg_cron, pg_net |
| Payments | Paystack inline checkout, settled server side and by signed webhook |
| Push | Web Push (VAPID) through a service worker, dispatched from `/api/push/dispatch` |
| Hosting | Netlify with the Next.js runtime |

## How access works

Row level security is the enforcement; the client only hides what a role cannot use.

- `member` sees only their own rows.
- `receptionist` sees members, payments, visits and revenue for their branch, plus members with no branch yet. `staff_covers(branch)` in `db/034` is the single rule every policy and payment function uses.
- `admin` sees everything.

Every security definer function has an explicit grant (`db/033`). Card payments are never confirmed by a person: the browser callback and the Paystack webhook both call `settleCardPayment` (`src/lib/card-settlement.ts`), which reads the charge back from Paystack and settles a reference once.

## Local setup

```bash
npm install
cp .env.example .env.local   # fill in the values below
npm run dev
```

### Environment

| Variable | Where it is used |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Browser and server. The anon key is public. |
| `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` | Card checkout in the browser |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | Push subscription in the browser |
| `SUPABASE_SECRET_KEY` | Server routes only |
| `PAYSTACK_SECRET_KEY` | Payment verification and webhook signature |
| `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Push dispatch |
| `PUSH_DISPATCH_SECRET` | Must equal `app_config.dispatch_secret`; the database sends it when it calls the dispatcher |
| `SUPABASE_PROJECT_REF`, `SUPABASE_DB_PASSWORD`, `SUPABASE_DB_REGION` | `npm run migrate` only |
| `APP_URL`, `TEST_ADMIN`, `TEST_DESK`, `TEST_PASSWORD` | Test suites only |

Generate VAPID keys with `npx web-push generate-vapid-keys`.

## Database

Migrations live in `db/` and are applied in filename order:

```bash
npm run migrate -- db/001_schema.sql db/002_security.sql ...
```

After the first run, set two rows the push trigger needs:

```sql
insert into app_config (key, value) values ('app_url', 'https://your-site.example')
on conflict (key) do update set value = excluded.value;
-- dispatch_secret is generated by db/036; copy it into PUSH_DISPATCH_SECRET
select value from app_config where key = 'dispatch_secret';
```

`db/036` also schedules a five minute pg_cron backstop that re-sends any notification a failed call left behind.

## Paystack

In the Paystack dashboard set the webhook URL to `https://your-site.example/api/paystack/webhook`. Keep test keys until the gym's own account is live.

## Tests

All suites run against the database in `.env.local` and remove what they create. None has a default target: set `APP_URL` explicitly.

```bash
npm run lint && npm run typecheck && npm run build
npm run test:security     # a signed-in member tries every escalation
npm run test:branches     # a receptionist stays inside their branch
npm run test:logic        # pricing, days and referral rules
APP_URL=http://localhost:3000 npm run test:push
APP_URL=http://localhost:3000 node scripts/ui/navigation.cjs   # Playwright phone suites, see scripts/ui
```

`scripts/clear-trial-data.js` and `scripts/seed-demo.js` write to the database and refuse to run without `--yes`.

## Deploy

Netlify builds `main` with `npm run build`. Set every variable from the table above in the site's environment first.
